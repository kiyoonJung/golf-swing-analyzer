# 골프 스윙 포즈 분석 (웹 프로토타입)

## 전체 흐름
1) [Python, 클럽·시점마다 1회] 프로 영상 → 단계별 기준 각도 JSON 추출
2) [웹] 클럽·시점 선택 → 사용자가 영상 업로드/카메라 촬영 → 브라우저에서 포즈 분석 → 기준 JSON과 비교 → 피드백

## 파일 이름 규칙 (assets/)
| 용도 | 이름 |
|---|---|
| 프로 영상 | `{클럽}_pro_{front|side}.mp4`   예: driver_pro_side.mp4, iron_pro_front.mp4 |
| 기준값 (자동 생성) | `reference_{클럽}_{front|side}.json` |
| 단계 확인 이미지 (자동 생성) | `reference_{클럽}_{시점}_stage0~6.jpg` |
| 시각표 (자동 생성) | `contact_sheet_{클럽}_{시점}.jpg` |
| 촬영 가이드 PNG (선택) | `{클럽}_guide_{front|side}.png` |

클럽 id: `driver`(드라이버), `iron`(아이언)

## 1단계: 기준값 만들기 (Python 3.8~3.12, mediapipe 0.10.14)
프로 영상 조건: 한 명, 전신이 계속 보임, 카메라 고정, 오른손잡이 기준.

    pip install -r tools/requirements.txt
    python tools/extract_reference.py assets/driver_pro_front.mp4 --club driver --view front
    python tools/extract_reference.py assets/iron_pro_side.mp4    --club iron   --view side

`--club`을 생략하면 driver 입니다.

자동 포착이 안 맞을 때(권장 방법):

    python tools/extract_reference.py assets/iron_pro_side.mp4 --club iron --view side --sheet
    → assets/contact_sheet_iron_side.jpg 에서 7단계 시각(초) 확인
    python tools/extract_reference.py assets/iron_pro_side.mp4 --club iron --view side --times 0.0,1.3,2.47,3.03,3.2,3.4,4.6
    (7단계 순서 — 아래 '스윙 7단계' 참고 / --start, --end 로 스윙 구간만 지정도 가능)

생성된 reference_*_stage0~6.jpg 7장이 실제 동작과 맞는지 반드시 눈으로 확인하세요.

## 스윙 7단계
| # | 단계 | 정의 (중간 3단계는 샤프트가 지면과 평행한 순간) | 자동 포착 규칙 (clubs.py / common.js) |
|---|---|---|---|
| 0 | 어드레스 | 테이크어웨이 직전 정지 자세 | 백스윙 최고 속도 지점에서 거꾸로 가서 손이 멈춘 마지막 프레임 |
| 1 | 테이크어웨이 | 백스윙 중 샤프트 평행 | 어드레스→탑 손목 상승량의 25% 를 처음 넘는 프레임 |
| 2 | 백스윙 탑 | 다운스윙 전환 직전 | 임팩트 전 손목이 가장 높은 프레임 |
| 3 | 다운스윙 | 다운스윙 중 샤프트 평행 | 탑→임팩트 손목 하강량의 70% 를 처음 넘는 프레임 |
| 4 | 임팩트 | 공을 맞히는 순간 | 손목 속도가 가장 빠른 프레임 |
| 5 | 팔로우 스루 | 임팩트 후 샤프트 평행 | 임팩트→피니시 손목 상승량의 30% 를 처음 넘는 프레임 |
| 6 | 피니시 | 스윙이 끝나 멈춘 자세 | 임팩트 후 손이 거의 멈추는 첫 프레임 |

- 자동 포착은 --times 를 안 줬을 때의 보조 수단. 프로 기준값은 --times 로 직접 지정 권장
- 사용자 영상은 규칙이 아니라 기준 자세(손목 위치)와 가장 비슷한 장면을 순서대로 찾음 → 단계 수에 상관없이 동작
- 기존 4단계 기준 JSON 도 그대로 동작 (단계 수는 기준 JSON 을 따름). 7단계로 쓰려면 아래 명령으로 다시 추출
- 머리 위치 비교 단계와 처음 보여줄 단계는 clubs/*.js 의 headStages, defaultStage

현재 드라이버 프로 영상(정면·측면 모두 30fps, 5.7초)의 7단계 시각 (1프레임 단위로 확인함, 두 영상은 서로 다른 스윙이라 시각이 조금 다름):

    python tools/extract_reference.py assets/driver_pro_front.mp4 --club driver --view front --times 0.0,1.23,2.47,3.07,3.2,3.37,4.6
    python tools/extract_reference.py assets/driver_pro_side.mp4  --club driver --view side  --times 0.0,1.3,2.47,3.03,3.2,3.4,4.6

백스윙 탑 = 2.47s (클럽이 가장 깊이 넘어간 뒤 다운스윙 전환 직전, 2.43~2.50s 범위)
정면: 테이크어웨이 37f, 다운스윙 92f, 팔로우 스루 101f / 측면: 39f, 91f, 102f (샤프트 평행 프레임)
피니시 = 4.6s(138f): 피니시 자세가 완성되어 움직임이 멈춘 순간. 영상 끝(5.6s)으로 잡으면 1초 넘게 자세를 유지하는 구간까지
포함돼, 손이 멈춘 순간을 피니시로 찾는 사용자 쪽과 기준이 달라짐 → 동기화 재생에서 프로가 갑자기 빨라지는 원인이었음

현재 아이언 프로 영상(정면·측면 모두 실시간 30fps, 1.73초, 51프레임, 키프레임 5프레임 간격으로 재인코딩)의 7단계 시각:

    py -3.12 tools/extract_reference.py assets/iron_pro_front.mp4 --club iron --view front --times 0.0,0.4,0.767,0.933,0.967,1.067,1.4
    py -3.12 tools/extract_reference.py assets/iron_pro_side.mp4  --club iron --view side  --times 0.0,0.433,0.767,0.933,0.967,1.067,1.6

정면: 0f / 12f / 23f / 28f / 29f / 32f / 42f, 측면: 0f / 13f / 23f / 28f / 29f / 32f / 48f (임팩트 = 공이 보이는 마지막 프레임)
- 정면·측면은 서로 다른 골퍼의 영상
- 슬로모션이 아닌 실시간 영상이라 탑→임팩트가 6프레임뿐 → 다운스윙(P6)과 임팩트가 1프레임 차이. 더 정밀하게 하려면 고속(슬로) 촬영 영상 필요
- iron.js 의 proSlowmo = 1 (실시간으로 판단한 추정값)
- 아이언 단계별 문구는 src/js/clubs/advice_iron.js (뒤땅·토핑, 핸드 퍼스트, 체중 왼발 이동 중심. 임시 초안)

## 2단계: 웹 실행 (로컬 서버 필수, 포트 8010)
    python serve.py                 # http://localhost:8010  (Windows 는 start.bat 더블클릭)
화면 위에서 클럽 → 시점 → 입력 방식을 고릅니다. serve.py 는 캐시를 끄므로 새로고침만 하면 최신 코드가 반영됩니다.

## 클럽별로 따로 고치는 곳
- 조언 문구 / 허용 오차(threshold): src/js/clubs/{클럽}.js
  - threshold 는 관절별: `{ shoulder: 15, elbow: 20, hip: 10, knee: 12 }` (시작값, 추정). 숫자 하나로 쓰면 모든 관절 공통
  - 상체 숙임·무릎은 작은 차이도 타점에 영향이 커서 엄격하게, 팔꿈치는 빠르게 움직이고 인식 오차가 커서 느슨하게
  - 피드백 카드는 허용 각도를 얼마나 넘었는지(초과량)가 큰 관절부터 보여주고, 문구에 "(허용 ±N°)" 표시
- 자동 포착 규칙: tools/clubs.py 의 detect_key_frames_{클럽}  (+ JS 쪽 detectKeyFrames, 구버전 JSON 보조용)
- 문구는 모두 임시 초안입니다. 골프 아는 사람의 검수가 필요합니다.

## 새 클럽 추가 순서 (예: 퍼팅 putter)
1. src/js/clubs/putter.js 작성 (iron.js 를 복사해서 시작) → src/js/clubs/index.js 의 CLUBS 에 등록
2. tools/clubs.py 에 detect_key_frames_putter 를 만들고 CLUBS 에 등록
   (퍼팅은 큰 백스윙이 없어 "손이 가장 높은 곳=탑" 규칙이 안 맞음 → 단계 정의부터 새로 정할 것)
3. assets/putter_pro_front.mp4 등 영상을 넣고 extract_reference.py --club putter 로 기준값 생성
4. 웹에서 클럽 버튼이 자동으로 생기므로 화면 수정은 필요 없음

## 동작 포착 방식 (자세 유사도 매칭)
- 프로 영상: 사람이 정한 단계 시점의 "관절 각도(비교용)" + "손목 위치 특징(장면 찾기용)"을 JSON에 저장
- 사용자 영상: 기준 손목 위치와 가장 비슷한 프레임을 단계별로 찾음 (순서 제약 적용)
- 비교는 찾은 프레임의 관절 각도로 수행 → 장면 찾기 기준과 비교 기준을 분리해 틀린 자세가 숨지 않게 함

## 영상 재생 (src/js/player.js)
- 영상마다 재생/정지, 배속(0.12·0.25·0.5·0.75·1x), 탐색 슬라이더
- 배속은 "실제 스윙 속도" 기준. 프로 영상은 파일 자체가 슬로모션이라 clubs/*.js 의 proSlowmo 배율만큼 빠르게 재생해 1x = 실제 속도
  - 드라이버 프로 영상 proSlowmo = 2.75 (추정: 영상 탑→임팩트 22프레임 ÷ 투어 선수 실제 다운스윙 약 8프레임@30fps)
  - 프로 영상을 바꾸면 다시 재서 입력. 사용자 영상은 실제 속도로 찍혔다고 가정
- 재생 모드
  - 개별 재생: 두 영상을 따로 조작
  - 동기화 재생 (템포 비교용): 어드레스 시점을 맞춰 동시에 출발하고, 두 영상 모두 고른 배속의 일정한 실제 속도로 끝까지 재생.
    프로를 사용자에 맞춰 변속하지 않으므로 누가 탑·임팩트에 먼저 가는지 템포 차이가 그대로 보임. 자세 비교는 단계 버튼으로.
    "동기화 재생" 모드로 바꾸면 두 영상이 어드레스로 이동. 동기화 중 단계 버튼으로 자세를 본 뒤 ▶ 를 누르면 어드레스부터 다시 재생
    (재생 중 ⏸ 후 ▶ 는 그 자리에서 이어감).
    배속·재생 버튼은 두 영상 공통.
  - 동작 맞춤 재생 (자세 흐름 비교용): 단계(테이크어웨이·탑·임팩트…)를 비슷한 타이밍에 넘어가도록 프로가 변속.
    단계 시각 쌍을 부드러운 곡선(buildCurve, 단조 3차 보간)으로 잇고, 끊겨 보이지 않게
    프로 속도를 정속의 0.5~2배로 제한 + 속도 변화 완충(약 0.15초). 실측: 단계 통과 시 어긋남 ±0.04초 이내,
    프레임당 속도 변화 최대 5%, 위치 점프는 재생 시작 때 1~2회. 템포 차이는 지워지므로 템포 비교는 동기화 재생으로.
    모드를 바꿀 때와 단계 버튼 후 ▶ 를 누를 때 어드레스로 이동하는 동작은 동기화 재생과 같음
  - 분석 전에는 단계 시각이 없어 같은 실제 속도로 함께 재생만 함
- 스켈레톤 켜기/끄기: 영상마다 "스켈레톤" 버튼 (끄면 영상만 보고 비교 가능. 피드백 갱신은 계속됨)
- 프로 스켈레톤은 단계별로 저장된 자세라서, 프로 영상이 그 단계 시각(±1프레임)에 멈춰 있을 때만 표시
  (재생 중이거나 다른 시각에 멈춰 있으면 표시 안 함 → 동기화 재생 후 피니시 화면에 다른 단계 자세가 겹치지 않음)
- 동기화 중 사용자 영상이 멈추거나 끝나면 프로 영상을 정확한 대응 위치로 맞춤
- 동기화 보정: 작은 어긋남은 프로 재생 속도로 메움(동기화 ±10%, 동작 맞춤 ±30%). 실제 동작 시간으로 0.25초 넘게 어긋날 때만 위치 이동(seek)
  (seek 은 키프레임부터 다시 풀어야 해서 화면이 멈칫·점프함. 수정 전 0.75x 에서 프로 영상이 초당 5프레임만 그려지던 원인)
- 재생 중(개별·동기화 모두)에는 피드백 카드를 숨기고, 두 영상이 모두 멈추면 다시 표시

### 프로 영상 인코딩 (키프레임 간격)
원본 프로 영상은 키프레임이 0초·5.27초 2개뿐이라 탐색(단계 버튼, 슬라이더, 동기화 보정)이 느렸음.
→ 5프레임마다 키프레임을 넣어 다시 저장함 (프레임 수·시각 동일, 기준 JSON 재생성 불필요, 화질 PSNR 46~50dB).
새 프로 영상을 넣을 때도 같은 방식으로 저장 권장:

    ffmpeg -i 원본.mp4 -map 0 -c:v libx264 -preset veryfast -crf 18 -g 5 -keyint_min 5 -sc_threshold 0 -pix_fmt yuv420p -c:a copy -movflags +faststart assets/driver_pro_front.mp4
- 개발 서버(serve.py / http.server)는 영상 중간 탐색(Range)을 지원하지 않으므로 영상은 blob URL 로 재생해야 탐색·동기화가 됨 (현재 앱은 그렇게 함)

## 단계별 피드백 (과함 / 적당함 / 부족함 + 미스샷)
- buildStage 가 각도 차이를 부호까지 저장 (signed = 사용자 - 프로). + 면 과함, - 면 부족함, ±허용 오차 이내면 적당함
- 각도가 크다/작다의 의미: 어깨 = 팔이 몸통에서 들림/붙음, 팔꿈치 = 펴짐/접힘, 엉덩이 = 상체 세워짐/숙여짐, 무릎 = 펴짐/굽음
- 피드백 한 줄 = "[부위(좌우) 과함] 상태(수치, 자동 생성) + 고치는 법 + ⚠ 나오기 쉬운 미스샷"
  예) 엉덩이(오른쪽) 과함 — 상체가 프로보다 16° 더 세워져 있어요. 어드레스의 숙인 각도를 유지… ⚠ 미스샷: 얼리 익스텐션으로 토핑, 생크, 푸시·훅
- 문구 데이터: src/js/clubs/advice_driver.js (STAGE_ADVICE[단계][부위] = { over:{fix,miss}, good, under:{fix,miss} })
  아이언은 지금 같은 파일을 사용 (TODO: advice_iron.js). 단계 문구가 없으면 clubs/*.js 의 advice[시점][부위] 공통 문구로 대체
- 모든 문구·미스샷은 초안. 골프 아는 사람의 검수 필요

## 머리 위치 비교 (analyzer.js headPoint / addHeadDiffs)
- 머리 중심 = 화면의 머리 원 중심 (두 귀 중점을 목 방향으로 약간 올린 점). 원과 비교가 같은 점을 씀
- "어드레스 대비 머리 이동량"을 프로·사용자 각각 몸통 길이 단위로 계산 → 그 차이가 0.15(머리 폭의 약 1/3)를 넘으면 지적
- 비교 단계: 테이크어웨이, 백스윙 탑, 다운스윙, 임팩트 (clubs/*.js headStages. 어드레스는 기준, 팔로우 스루·피니시는 몸을 돌려 머리가 움직이는 게 정상이라 제외)
- 표시: 사용자 머리 원 초록/빨강(비교 안 하는 단계는 흰색), 차이가 크면 프로 머리 원도 빨강, 피드백 카드 맨 위에 방향·크기 안내
- 방향 표현: 정면 = 타깃 쪽/반대쪽·위/아래, 측면 = 공 쪽(앞)/뒤·위/아래 (오른손잡이, 프로와 같은 방향 촬영 기준)
- 프로 값은 기준 JSON 의 landmarks 로 계산하므로 Python 수정 불필요. 조언 문구는 clubs/*.js 의 advice[view].head
- 기준값 0.15 는 임시값 (실측: 프로 탑·임팩트 머리 이동 0.03~0.18). 일반인 영상으로 조정 필요

## 측면 영상의 먼 쪽 다리
측면(오른손잡이, 타깃 반대편에서 촬영)에서는 왼다리가 오른다리 뒤에 겹쳐 MediaPipe 가 "보인다"고 해도 틀린 곳에
찍는 일이 잦음 (예: 프로 어드레스 왼발목이 오른다리 정강이 위에 visibility 0.58 로 찍힘).
→ 측면에서는 hip_L, knee_L 각도를 비교·피드백에서 제외하고(analyzer.js VIEW_EXCLUDE), 왼다리는 항상 점선으로 표시(ui.js FAR_LEG).
   기준 JSON 에 값이 있어도 무시되므로 Python 쪽은 바꿀 필요 없음.

## 알려진 한계
- 오른손잡이 기준, 프로와 사용자가 같은 방향에서 촬영해야 함
- 측면 영상은 가려진 관절이 많아 단계에 따라 비교 가능한 각도가 적을 수 있음
- 2D 각도라서 촬영 각도 차이에 민감함

## MediaPipe 오인식 보정 (analyzer.js cleanupPose / extract_reference.py cleanup_pose, 두 쪽 규칙 동일)
각도 계산 전에 자동으로 실행되며, 분석 완료 문구 끝에 보정 횟수가 표시됨.
1. 좌우 뒤집힘: 백스윙 탑에서 팔이 얼굴을 가리고 몸통이 크게 돌면 MediaPipe 가 "등진 사람"으로 착각해
   몸 전체의 왼쪽/오른쪽 이름을 뒤바꿈 (실측: 정면 사용자 영상 1.08~1.72초, 20프레임 연속).
   → 두 발은 스윙 중 제자리라는 규칙으로, 발목이 평소와 반대로 붙은 프레임의 좌/우 랜드마크를 맞바꿈.
   두 발이 가까운 측면 영상(몸통 길이 30% 미만)에서는 판단이 불확실해 보정하지 않음.
2. 하체 순간 튐: 1~2프레임만 발목 등이 다리 사이로 찍혔다 돌아오는 경우 앞뒤 ±3프레임 중앙값으로 교체.
   교체한 점은 visibility 0 → 화면에는 점선, 각도 비교에서는 제외. 피니시의 뒷발처럼 서서히 움직이는 건 건드리지 않음.

## 진단 모드 (포즈 인식이 이상할 때)
- `http://localhost:8010/?debug=1` → 분석 후 `pose_debug_track.json` 자동 다운로드 (평소 방식: 앞 프레임을 이어서 추적)

## 스켈레톤 표시 (ui.js)
- 머리: 코·양쪽 귀 평균 위치에 원 (반지름 = 몸통 길이 × HEAD_RATIO)
- 가려진 관절(visibility ≤ 0.4)은 점선으로 "추정" 표시 (completePose)
  - 손목: 한쪽만 가려지면 보이는 손목 위치 사용 (두 손이 그립을 함께 잡으므로)
  - 팔꿈치: 반대쪽 팔 마디 길이로 어깨~손목 사이 위치 계산
  - 무릎: 반대쪽 다리의 굽은 모양(비율)을 엉덩이~발목 선에 옮겨 붙임
    (측면에서 가려진 다리는 멀어서 짧게 보이므로 길이를 빌리면 무릎이 앞으로 튀어나감 → 비율 사용)
  - 반대쪽도 안 보이면 MediaPipe 추정 좌표를 그대로 점선으로 표시
  - 추정 좌표는 그림 전용. 각도 비교에는 쓰지 않음 (보이는 관절끼리만 비교)

## 미세 조정 슬라이더
- 분석 후 단계 버튼(어드레스/탑/임팩트/피니시)을 누르면 아래에 "미세 조정" 패널이 나타남
- AI가 찾은 프레임 ±12프레임 범위에서 슬라이더 또는 ◀ ▶ (1프레임씩)로 정확한 순간에 맞춤
  (15초가 넘는 긴 영상은 분석 간격이 1/30초보다 넓어져 버튼이 "1칸"으로 바뀌고, 1칸의 실제 시간이 함께 표시됨)
- 조정하면 그 프레임의 관절 각도로 오차·피드백·칩 색이 즉시 다시 계산됨
- 앞/뒤 단계와 순서가 뒤바뀌지 않도록 범위가 자동 제한되고, "AI 위치로" 버튼으로 되돌릴 수 있음
- 관련 코드: analyzer.js (buildStage, adjustRange), ui.js (showAdjuster), app.js (moveStage)

## 간편 실행 (Windows)
`start.bat` 을 더블클릭하면 서버가 켜지고 브라우저가 자동으로 열립니다. 끌 때는 검은 창을 닫으면 됩니다.
(이미 서버가 켜져 있으면 포트 오류가 나므로, 그땐 브라우저에서 http://localhost:8010 만 열면 됩니다.)

## 서버 (serve.py)
`start.bat` 은 `serve.py` 를 실행합니다. python -m http.server 와 같지만 브라우저가 파일을 저장해 두지 않게
(Cache-Control: no-store) 해서, 코드를 고친 뒤 새로고침만 해도 항상 최신 파일이 로딩됩니다.
수동 실행: python serve.py        (다른 포트: python serve.py 8020)
